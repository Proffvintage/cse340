```js
const getProjectsByCategoryId = async (categoryId) => {
  const query = `
    SELECT p.project_id, p.organization_id, p.title, p.description, p.location,
           TO_CHAR(p.date, 'YYYY-MM-DD') AS date, o.name AS organization_name
    FROM project AS p
    JOIN organization AS o ON o.organization_id = p.organization_id
    JOIN project_category AS pc ON pc.project_id = p.project_id
    WHERE pc.category_id = $1
    ORDER BY p.date, p.project_id;
  `;
  const result = await db.query(query, [categoryId]);
  return result.rows;
};
```

```js
app.use((req, res, next) => {
  const error = new Error('Page Not Found');
  error.status = 404;
  next(error);
});

app.use((error, req, res, next) => {
  if (res.headersSent) return next(error);
  const invalidIdentifier = error.code === '22P02';
  let status = 500;
  if (error.status === 404 || invalidIdentifier) status = 404;
  console.error('Request failed:', {
    path: req.path,
    status,
    code: error.code || 'SERVER_ERROR',
    message: error.message,
  });
  let title = 'Service Temporarily Unavailable';
  if (status === 404) title = 'Page Not Found';
  res.status(status).render(`errors/${status}`, {
    title,
    currentPath: req.path,
    error: error.message,
    stack: error.stack,
  });
});
```

Why must the catch-all middleware come after the application router?

MARKSON:
Express processes middleware in order. The catch-all should run only when no defined route handled the request, or it would turn valid pages into 404 responses.

COACH:
Correct. Why does it create an error and call `next(error)`?

MARKSON:
That sends missing-route responses through the same centralized handler as missing database resources and unexpected failures. One place controls status codes, logging, and templates.

COACH:

MARKSON:
It has four parameters, with the error object first.

COACH:
Correct. What is the semantic difference between a 404 and a 500 response?

MARKSON:
A 404 means the requested route or resource is unavailable. A 500 means the server encountered an unexpected failure while processing an otherwise valid request.

COACH:
Good. Why does the handler check `res.headersSent`?

MARKSON:
It avoids trying to send another response after headers have already gone to the client. Passing the error onward lets Express handle that partial-response case.

COACH:
Correct. Why is the detailed error logged while the production page remains generic?

MARKSON:
Logs help developers diagnose the problem, but stack traces and query details can expose internal paths or credentials. Production visitors should receive a safe message without sensitive internals.
