```js
const processNewProjectForm = async (req, res) => {
  if (await redirectValidationErrors(req, res, projectFields)) return;
  if (await redirectMissingOrganization(req, res)) return;

  try {

    await redirectWithSession(req, res, `/project/${projectId}`);

    if (await redirectOrganizationRace(req, res, error)) return;
    throw error;
  }
};
```

MODEL COACH:
This is the session configuration from server.js:24-35. What state does this middleware preserve across requests?

```js
app.use(session({
  secret: sessionSecret,
  resave: false,
  saveUninitialized: false,
  cookie: {
    maxAge: 60 * 60 * 1000,
    httpOnly: true,

```

SUGGESTED MARKSON RESPONSE:
HTTP requests do not remember previous requests automatically. The session associates a browser's session cookie with temporary server-side data. This project uses that data for flash feedback and retained form values. It uses in-memory storage for the Week 4 activity rather than treating the session as a new database account system.

SUGGESTED MARKSON RESPONSE:
The refreshed page repeats a GET, not the original POST. The controller saves the record, returns HTTP 303 with a destination, and the browser requests that page. Refreshing the detail page therefore does not repeat the insert or update.

MODEL COACH:

SUGGESTED MARKSON RESPONSE:
It ensures the flash message and retained values have been saved before the browser follows the redirect. If the save fails, the promise rejects and error handling can respond instead of pretending the feedback was safely stored.

SUGGESTED MARKSON RESPONSE:
The middleware exposes the req.flash function as res.locals.flash without calling it. The shared header calls flash when a page is rendered. That call retrieves and clears the messages. Redirect responses and static assets do not render the header, so they do not consume the feedback.

MODEL COACH:
What does the one-hour cookie maximum mean in units?

SUGGESTED MARKSON RESPONSE:
Express cookie maxAge is measured in milliseconds. Multiplying 60 minutes by 60 seconds and 1000 milliseconds produces one hour. The cookie stores a session identifier, not a copy of all the server-side form data.

SUGGESTED MARKSON RESPONSE:
It signs the session identifier cookie so a client cannot create an accepted identifier by simply changing the cookie. TOPIC 4: SERVER-SIDE VALIDATION

MODEL COACH:
This is actual category validation from src/controllers/categories.js:13-18. Why does it check the type before trimming and checking the length?

```js
const categoryValidation = [
  body('name')
    .custom((value) => typeof value === 'string').withMessage('Category name is required').bail()
    .trim().notEmpty().withMessage('Category name is required').bail()
    .isLength({ min: 3, max: 100 }).withMessage('Category name must be between 3 and 100 characters'),
];
```

SUGGESTED MARKSON RESPONSE:
A request can contain a missing value, array, object, boolean, or other unexpected type instead of a text field. Rejecting those before sanitization avoids converting them into apparently valid strings. Trimming then prevents whitespace-only names, and the length rule enforces the assignment's 3-to-100-character requirement.
