2. DATABASE DESIGN AND RECREATION SCRIPT

Created src/setup.sql with a BEGIN/COMMIT transaction, all table definitions,
relationship indexes, and INSERT statements. It is a one-time setup script for
an empty application schema. It does not delete existing tables or run on
application startup. A transaction prevents partially completed initialization.

organization table:
- organization_id: SERIAL PRIMARY KEY.
- name: VARCHAR(150) NOT NULL.
- description: TEXT NOT NULL.
- contact_email: VARCHAR(255) NOT NULL.
- logo_filename: VARCHAR(255) NOT NULL.

project table:
- project_id: SERIAL PRIMARY KEY.
- organization_id: INTEGER NOT NULL, foreign key to organization.organization_id.
- title: VARCHAR(150) NOT NULL.
- description: TEXT NOT NULL.
- location: VARCHAR(255) NOT NULL.
- date: DATE NOT NULL.
- An index on organization_id supports sponsor joins.

category table:
- category_id: SERIAL PRIMARY KEY.
- name: VARCHAR(150) NOT NULL UNIQUE.

project_category table:
- project_id: foreign key to project.project_id, NOT NULL.
- category_id: foreign key to category.category_id, NOT NULL.
- PRIMARY KEY (project_id, category_id) prevents duplicate associations.
- ON DELETE CASCADE removes links when their project or category is deleted.
- An index on category_id supports lookups from categories to projects.

One organization can sponsor many projects. Each project has exactly one
sponsor through its required organization_id. Many-to-many membership is
represented by project_category, so a project can have several categories and a
category can contain several projects. All seeded projects have categories and
all seeded categories have projects. Future inserts must also create category
links when adding projects; a foreign key alone does not require a parent
record to have at least one junction row.

4. NODE.JS MODEL FILES AND DATABASE CONNECTION

Created src/models/db.js:
- Creates one reusable pg connection pool with SSL and query/connection timeouts.
- Accepts Render's self-signed certificate only for its private dpg-* database
  hostname; external database connections retain certificate verification.
- Accepts DB_URL, the lesson's variable name, or the existing DATABASE_URL.
- Exports the pool as the default export and exports testConnection.
- Tests connectivity with SELECT NOW().
- Supports development query timing and row-count logging when
  ENABLE_SQL_LOGGING=true. It does not log database credentials.
- Reports idle connection failures and permits orderly pool shutdown.

Created src/models/organizations.js:
- Exports getAllOrganizations as an asynchronous arrow function.
- Selects organization_id, name, description, contact_email, and logo_filename.
- Orders by organization_id and returns result.rows.

Created src/models/projects.js:
- Exports getAllProjects as an asynchronous arrow function.
- Joins project to organization to retrieve organization_name.
- Retrieves IDs, title, description, location, and date.
- Returns dates as YYYY-MM-DD strings to preserve the calendar date.
- Orders projects by date and project_id, and returns result.rows.

Created src/models/categories.js:
- Exports getAllCategories as an asynchronous arrow function.
- Selects category_id and name, orders by category_id, and returns result.rows.

Queries explicitly select columns. Database failures are allowed to reject so
route handlers can handle them consistently. Data access stays in the dedicated
model files, following the exact file/function names used in the lessons.

5. EXPRESS ROUTES AND ERROR BEHAVIOR

Updated server.js to import and await the model functions inside /organizations,
/projects, and /categories. Each handler passes its results to the matching EJS
view together with its title and navigation state. The home page retrieves all
three collections concurrently and uses the results for partner links, category
previews, and the next three project previews.

Removed the static directory arrays from src/data/site.js; only navigation
remains there. Database data is fetched on each page request rather than copied
into a hardcoded application array.

Added try/catch and next(error) to asynchronous routes because this project uses
Express 4. Added a shared src/views/error.ejs page. Query failures return HTTP
500 with a useful message and without SQL or credentials. Missing routes return
HTTP 404. Successful empty queries remain HTTP 200 and directory pages show an
empty-state message. The connection is tested before the server begins listening.
SIGINT and SIGTERM close the HTTP server and database pool.

Request flow:
Browser -> Express route -> await model -> pg/PostgreSQL -> result.rows ->
res.render -> EJS and shared partials -> HTML response -> browser.
